# Changelog

## [2.0.9] - 2026-09-12

- Для `FL_NONRESIDENT` восстановлен общий минимум контактов: российский
  `phone` или `email`. Один `foreignPhone` больше не удовлетворяет этому
  правилу, поскольку он не может быть сохранён как телефон карточки ЦФТ.
- Отдельная условная обязательность `foreignPhone` при иностранном блоке и
  отсутствии российского телефона, а также международная проверка формата
  сохранены.
- Положительный сценарий «только `foreignPhone`» заменён отрицательным;
  добавлен положительный сценарий `email + foreignPhone`.

## [2.0.8] - 2026-09-11

- Иностранный телефон теперь удовлетворяет правилу минимального контакта для
  `FL_NONRESIDENT` наравне с российским телефоном и электронной почтой.
- Контактные правила `FL_RESIDENT`, `IP_RESIDENT` и замороженного
  `IP_NONRESIDENT` не изменены.
- Добавлены положительный sample и прямой контрактный тест заявки только с
  валидным `foreignPhone`.

## [2.0.7] - 2026-09-11

- Иностранный налоговый адрес и почтовый адрес больше не обязательны при
  регистрации `FL_NONRESIDENT` и `IP_NONRESIDENT`: оба поля могут отсутствовать.
- Обязательность страны иностранного налогового резидентства, иностранного ИНН
  или причины его отсутствия, а также запрет `US` сохранены.
- Удалены ошибочное правило и код
  `BEN.TAX.FOREIGN_ADDRESS.OR_POSTAL_REQUIRED`; добавлены прямые регрессии для
  обоих нерезидентских сценариев.

## [2.0.6] - 2026-09-11

- Для миграционной карты добавлена проверка номера: 7 или 11 цифр без серии
  либо раздельная форма из 4 цифр серии и 7 цифр номера.
- При передаче любого поля `addDoc` теперь обязателен технический `typeCode`;
  частичное обновление при этом не требует отсутствующие поля документа.
- Для ВНЖ и РВП серия и дата окончания больше не считаются безусловно
  обязательными; номер и дата начала при регистрации остаются обязательными.
- Добавлены эталонные векторы оператора, прямые контрактные тесты и samples для
  всех допустимых форм миграционной карты и новых ошибок.

## [2.0.5] - 2026-09-11

- Регистрационный адрес `FL_RESIDENT` теперь допускает только код страны `RU`
  как в полной проверке, так и при частичном обновлении адреса.
- Разрешённая иностранная страна возвращает обычную ошибку данных
  `BEN.ADDR.REG.COUNTRY.MUST_BE_RU`; код `US` сохраняет отдельный регуляторный
  отказ без дублирующей ошибки.
- Добавлены отдельный sample и прямые тесты российского адреса, иностранной
  страны, `US`, неверного формата и частичного обновления.

## [2.0.4] - 2026-09-10

- `FL_NONRESIDENT` теперь отклоняет российское гражданство обычной ошибкой
  данных; допустимое иностранное гражданство принимается, а `US` остаётся
  отдельным регуляторным отказом.
- Полная регистрационная проверка ФЛ-нерезидента требует код страны адреса:
  для `RU` обязательна ФИАС-структура, для разрешённой иностранной страны —
  полная строка, код `US` отклоняется.
- Адресный контракт частичного обновления ФЛ-нерезидента не изменён.
- Добавлены отдельные samples и прямые тесты гражданства и адресных веток.

## [2.0.3] - 2026-09-10

- Удалено определение США по свободному тексту
  `beneficiary.fl.birthPlace` и
  `beneficiary.tax.foreignTaxResidency.address` во всех проверках ФЛ и ИП.
- Обязательность места рождения и иностранного адреса в применимых сценариях
  сохранена. Страна определяется только по отдельным кодам, а регуляторные
  признаки США — по соответствующим логическим полям.
- Удалены четыре дублирующих правила места рождения и общий текстовый контроль
  иностранного налогового адреса вместе с больше не нужными условиями.
- Добавлены прямые проверки регистрации и обновления: `RUSSIA`, `USA`, `США`
  и `United States of America` в свободном тексте не влияют на страну, тогда
  как структурированный код `US` по-прежнему даёт регуляторный отказ.

## [2.0.2] - 2026-09-08

- Запрет почтового адреса в США теперь проверяется по
  `beneficiary.contacts.postalAddressCountryCode = US`, а не по словам в
  свободном тексте `postalAddress`.
- Сохранены код ошибки `BEN.CONTACTS.POSTAL.NOT_US` и уровень `EXCEPTION`;
  поле ошибки изменено на `beneficiary.contacts.postalAddressCountryCode`.
- Добавлены прямые проверки всех затронутых регистрационных сценариев ФЛ/ИП,
  адресных веток обновления ФЛ/ИП-резидента и случая, когда текст содержит
  `USA`, но отдельный код страны не равен `US`.

## [2.0.1] - 2026-09-08

- Полные проверки `FL_RESIDENT`, `FL_NONRESIDENT`, `IP_RESIDENT` и
  `IP_NONRESIDENT` теперь всегда требуют логические поля
  `foreignTaxResident`, `usTaxResident` и `usResident`.
- Отсутствие, `null` и пустая строка возвращают ошибку `.REQUIRED`; строка,
  число, массив и объект возвращают ошибку `.BOOL`. Значение `false` остаётся
  заполненным логическим значением.
- В частичных проверках обновления отсутствие поля по-прежнему означает «не
  изменять», а переданные `null` и значения неверного типа больше не
  пропускаются.
- Допустимые значения и действующие регуляторные отказы для резидентов и
  нерезидентов не изменены. Добавлены отдельные примеры и общая проверка
  граничных значений для всех затронутых сценариев.

## [2.0.0] - 2026-09-03

- Только при регистрации `UL_RESIDENT` юридический адрес теперь требует
  `regionCode`, `postalCode`, `city` или `locality`, `streetType`, `street`,
  `house`. Прежнее требование `countryCode = RU` сохранено.
- `fullAddress` больше не обязателен при заполненной структуре и не может
  заменить её. Это несовместимое изменение регистрационного контракта.
- Для отсутствующих полей добавлены подробные ошибки `.REQUIRED`, для
  нестроковых значений и строк из пробелов - `.FORMAT`.
- Обновление ЮЛ-резидента, остальные типы и отвязка сохраняют прежние правила.
- Добавлены примеры адреса с городом и населённым пунктом без полной строки,
  неполной структуры, пустых значений и сохранения контракта обновления ЮЛ.
- Зависимость `fast-uri` в lock-файле обновлена с `3.1.5` до `3.1.7` для
  устранения найденных уязвимостей. Бизнес-правила от этого не меняются.

## [1.1.6] - 2026-08-21

- Отсутствующий `beneficiary.fl.citizenshipCode` теперь возвращает обычную
  ошибку заполнения `FL.CITIZENSHIP.REQUIRED` уровня `ERROR` для полных
  проверок ФЛ и ИП.
- Проверки гражданства США остаются регуляторными отказами уровня `EXCEPTION`.
- Добавлены отдельные примеры отсутствующего гражданства для ФЛ-резидента,
  ИП-резидента и ИП-нерезидента; существующий пример ФЛ-нерезидента обновлён.

## [1.1.5] - 2026-07-24

- Обновлён рантайм-движок правил `@jsonspecs/rules` до `4.0.1`.
- Адрес регистрации `FL_NONRESIDENT` теперь всегда проверяется как российский
  и при регистрации, и при обновлении.
- `beneficiary.address.registration.countryCode` больше не обязателен для
  `FL_NONRESIDENT`; переданное старым клиентом значение принимается, но не
  влияет на проверки. Отдельный отказ для значения `US` удалён, при этом
  проверки гражданства, места рождения и налоговых признаков США сохранены.
- `fullAddress` для обновления `FL_NONRESIDENT` больше не обязателен: полная
  строка должна появиться после нормализации адреса процессором.
- Добавлены примеры регистрации и обновления без `countryCode` и
  `fullAddress`, неполной структуры, пустых значений и совместимости со
  старыми значениями `US` и `TM`.
- Служебные поля `state`, `cityId`, `cityFias`, `streetId` и `streetFias` без
  содержательной российской структуры больше не обходят обязательные проверки
  адреса.

## [1.1.3] - 2026-07-24

- Требование полного адреса (`fullAddress`) снято для обновления ФЛ-резидента и ИП-резидента: для российского адреса достаточно структурных полей (регион, город, улица, тип улицы, дом, индекс), полную строку собирает процессор через адаптер нормализации. У ФЛ-нерезидента адрес иностранный, поэтому `fullAddress` остаётся обязательным.

## [1.1.2] - 2026-07-24

- Для `UL_NONRESIDENT` добавлена частичная проверка переданных КПП, КИО,
  страны и даты регистрации, страны налогового резидентства и иностранного
  налогового номера.
- Добавлены положительный пример обновления сведений об организации и
  налогового блока и отрицательный пример с неверным кодом страны.
- Исправлена частичная проверка документа ФЛ-нерезидента: иностранные
  документы используют свой справочник и не проверяются как паспорт РФ.

## [1.1.1] - 2026-07-24

- Адрес в заявке на обновление теперь проверяется как единый блок: обязательны
  `fullAddress` и `countryCode`, а российский адрес проходит действующие
  структурные проверки регистрации.
- Для `FL_RESIDENT` и `IP_RESIDENT` подключена проверка формата
  `beneficiary.contacts.foreignPhone`.
- Добавлены примеры на неполный адрес и некорректный иностранный телефон.

## [1.1.0] - 2026-07-24

- Добавлены точечные проверки обновления карточек: экспорты `entrypoints.<type>.update_validation` для FL-резидента, FL-нерезидента, ИП-резидента, ЮЛ-резидента и ЮЛ-нерезидента.
- Обновление проверяет только переданные поля в том же формате, что и регистрация: обязательность полей не навязывается, но формат и комплаенс присланных данных сохранены (гражданство и место рождения не США, налоговые флаги ФЛ/ИП по присутствию).
- Для ЮЛ набор обновления ограничен контактами и юридическим адресом.
- Добавлены переиспользуемые `library.documents.pred_type_code_present` и `library.documents.cond_type_code_in_dictionary_if_present` для условной проверки кода документа по справочнику.
- 12 новых примеров: успех по частичной заявке, ошибка формата почты и комплаенс-отказ по гражданству США.

## [1.0.0] - 2026-07-22

- Авторский проект переведён на jsonspecs/spec 1.0.0-rc.7, Rules 4.0.0 и CLI 4.0.1.
- Сборка fv1 заменена закрытой сборкой fv2 с явными `exports`.
- Унифицированы проверяющие правила и предикаты, строковые шаги, объекты `issue` и ссылки на справочники.
- Доменные операторы переведены на закрытый контракт `{schema, evaluate}` и покрыты эталонными векторами.
- `manifest.catalog` стал единственным источником редакторских метаданных; старые контракты полей и проверки прежнего движка удалены.
- Неподдерживаемые регулярные выражения заменены переносимыми выражениями профиля RC.7.
- Добавлено явное правило для `context.currentDate`, удалены восемь недостижимых артефактов.
- Закрыты пробелы в проверках дат, восстановлены условия для паспортных проверок и сравнений дат, отклоняются нестроковые ИНН.
- Зафиксирована граница пакета Node.js 20+, расширены регрессионные векторы операторов.
- Для всех 71 полей заполнены описания, а 230 правил с ошибками связаны с разделами и пунктами бизнес-требований через `issue.meta`.
- В метаданных правил сохранены имя, `SHA-256` и справочная страница исходного DOCX.
- 114 выполняемых примеров покрывают все 230 кодов ошибок и применимые граничные случаи.
- Зависимые проверки типов, логических значений и кодов документов защищены условиями; код документа 35 получает отдельную бизнес-ошибку.

- Switched local `not_true` and `is_boolean` compatibility coverage to built-in jsonspecs operators.
- Raised the jsonspecs dependency range to `^2.3.1`.
- Added package provenance checks for engine version, snapshot compatibility, zero diagnostics, and runtime ruleset metadata.
